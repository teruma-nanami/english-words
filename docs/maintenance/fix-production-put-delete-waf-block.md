# ロリポップ本番環境でのPUT/DELETEリクエスト失敗の修正

## 目的・背景

- 本番環境（ロリポップ）で、単語の削除・編集を実行すると失敗する
- 原因は、ロリポップのWAF（不正アクセス防止機能）が生のHTTP `DELETE`・`PUT`リクエストを403でブロックしているため。Laravelアプリケーションには到達していない
- 検証の結果、`POST`リクエスト＋`X-HTTP-Method-Override`ヘッダー（Laravelのメソッドスプーフィング機能）を使うことでWAFを回避でき、正常に処理されることを確認済み

## 利用者

- 管理画面から単語・単語帳を編集・削除する管理者ユーザー

## 必要な挙動

- フロントエンドの共通送信処理（`adminFetch`）が、`PUT`・`PATCH`・`DELETE`を扱う際、実際のHTTP通信では`POST`メソッドを使用し、`X-HTTP-Method-Override`ヘッダーで本来のメソッドを伝える
- ローカル開発環境・本番環境のいずれでも同じ処理経路で動作する（環境による分岐はしない）

## 受け入れ条件

- [ ] ローカル開発環境で、単語の編集・削除が引き続き正常に動作する
- [ ] ローカル開発環境で、単語帳の削除が引き続き正常に動作する
- [ ] 本番環境で、単語の削除が実際に成功する（204が返り、一覧から消える）
- [ ] 本番環境で、単語の編集が実際に成功する（204が返り、内容が更新される）
- [ ] 本番環境で、単語帳の削除が実際に成功する

## 対象外

- バックエンド（Laravel）側のルート・コントローラの変更
- ロリポップのWAF設定自体の変更（管理画面側の対応）
- 単語作成（POST）など、既に正常に動作している機能

## 制約

- `frontend/src/api/httpClient.ts`（共通送信処理）のみの修正とする
- 既存のAPIエンドポイント・URL構成は変更しない
