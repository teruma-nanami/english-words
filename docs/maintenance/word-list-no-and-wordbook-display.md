# 単語一覧・編集画面でのNo（並び順）・単語帳表示

## 目的・背景

- 単語登録時（`AdminWordCreate.tsx`）には「No」（単語帳内の並び順、`wordbook_word.order`）の入力欄があるが、一覧画面・編集画面のどちらにも表示されていない
- 編集画面には「Noを変更したい場合は、単語を削除してから登録し直してください。」という注意書きがあるが、対象のNo自体がどこにも表示されておらず、利用者が現在の値を確認できない
- 一覧画面では、各単語がどの単語帳に属しているかも分からない
- 一覧・編集画面用のAPIレスポンス（`WordResource`）には`order`も単語帳情報も含まれていない

## 利用者

- 単語一覧を閲覧する全ユーザー（一覧画面のNo・単語帳表示）
- 管理画面で単語を編集する認証済みユーザー（編集画面のNo表示）

## 必要な挙動

- 単語一覧画面で、現在の「ID」列を「No」列に置き換えて表示する
- 単語一覧画面に、各単語が属する単語帳名を表示する列を追加する
- 単語編集画面で、Noを表示する（変更不可・読み取り専用）
- 単語帳に紐付いていない単語のNo・単語帳名は、値がないことが分かる表示にする
- 一覧・編集画面用のAPIレスポンスにNo（`order`）・単語帳名を含める

## 受け入れ条件

- [ ] 単語一覧画面のテーブルで、これまでの「ID」列が「No」列に置き換わり、各単語のNo（`order`）が表示される
- [ ] 単語一覧画面のテーブルに、各単語が属する単語帳名の列が表示される
- [ ] 単語編集画面で、対象単語の現在のNoが表示される
- [ ] 単語編集画面のNo表示欄は入力・変更ができない
- [ ] 単語帳に紐付いていない単語のNo・単語帳名は、値がないことが分かる表示になる

## 対象外

- 編集画面からのNoの変更・更新機能
- 一覧画面での絞り込み・並び替え機能（将来的な別要望として扱う）
- 単語が複数の単語帳に所属する場合の複数No・複数単語帳表示（既存の`ShowWordEditFormUseCase`と同様、最初の単語帳のみを対象とする）

## 制約

- 既存の`WordResource`のレスポンス形式に`order`・単語帳名フィールドを追加する（既存フィールドは変更しない）
- 単語編集APIの受け入れ項目（`UpdateAdminWordPayload`）は変更しない（No変更不可のため）
